# Mars 技术选型与开发流程

> Mars：一款面向 Windows 的个人工作记录与日报/周报生成桌面应用。
> 本文档记录产品定位、Logo 方案、技术选型、架构设计与里程碑，作为后续开发工作的依据。

## 1. 产品定位

Mars 用于记录个人工作内容、管理项目和附件，并自动汇总生成日报/周报，帮助用户减少重复整理时间。

核心原则：

- **本地优先**：数据保存在本机 SQLite，附件保存在本地目录，无需登录、不依赖云服务，启动即用。
- **记录即资产**：每条工作记录都可绑定项目、时间、标签与附件，成为可检索、可分析的数据。
- **自动汇总**：日报/周报由记录自动生成，模板可自定义。
- **安静高级**：苹果式极简界面，克制的信息层级，让记录与查看成为自然习惯。
- **可扩展 AI**：接入大模型后，可用自然语言查询数据并操作软件内的受控功能。

## 2. 品牌与 Logo 设计

### 2.1 设计理念

Logo 概念为「红色星球与轨道」：

- **中心圆点**代表火星，也是一条独立的工作记录；每天新增的记录像一颗颗星点。
- **倾斜轨道**代表持续的时间节奏与项目轨迹，同时呼应「每日记录、按周汇总」的工作流。
- **轨道上的小卫星**代表附件、里程碑与关联内容，暗示数据可以被追踪和抵达。

风格采用极简几何、单色、无渐变、大量留白；缩到 16px 时仍能辨识为「星球 + 轨道」，与 Ceres、Neptune 形成家族感但不重复。

### 2.2 品牌资产

资产位于 `assets/brand/`：

| 文件 | 用途 |
| --- | --- |
| `logo-symbol.svg` | 透明符号，浅色背景侧边栏、空态、页眉 |
| `logo-symbol-dark.svg` | 透明符号，深色背景 |
| `logo-icon.svg` | 圆角方块应用图标 |
| `logo-horizontal-light.svg` | 浅色背景横版字标 |
| `logo-horizontal-dark.svg` | 深色背景横版字标 |
| `logo-icon-1024.png` | 1024px PNG，用于 Tauri 图标生成 |
| `logo-symbol-1024.png` | 1024px 透明符号 PNG |
| `brand-board.html` | 品牌板：Logo、色彩、字体与 UI 预览 |

### 2.3 从 Logo 推导色彩

主色取自火星地表般的暖锈红，辅以冷灰石板色形成对比，避免界面沦为单一暖色：

| Token | 色值 | 角色 |
| --- | --- | --- |
| `mars.rust` | `#C3451F` | 主色，导航选中、主按钮、图表主色 |
| `mars.ember` | `#FF6B3D` | 强调色，深色模式主按钮、关键数字 |
| `mars.deep` | `#20110C` | 深色模式窗口底色 |
| `mars.coal` | `#2B1B15` | 深色模式卡片与悬浮层 |
| `mars.paper` | `#F5EFE8` | 浅色模式窗口底色 |
| `mars.paper-2` | `#FBF7F1` | 浅色模式卡片底色 |
| `mars.ink` | `#2B1A13` | 主文字 |
| `mars.muted` | `#8A7A70` | 次级文字 |
| `slate` | `#5B6670` | 冷灰结构色，抵消暖色单点 |

配色逻辑：

- 浅色模式：暖白纸感背景 + 深墨文字 + 锈红结构 + 冷灰次级信息。
- 深色模式：深暖黑背景 + 奶油白文字 + 亮烬色强调 + 半透明白玻璃层级。
- 锈红只用于「当前项目、关键操作、数据高亮」，避免大面积铺色。

### 2.4 Logo 使用规范

- 深色背景使用奶油白符号，浅色背景使用锈红符号。
- 安全间距：符号四周至少保留符号高度 25% 的空白。
- 最小尺寸：16px（仅符号），48px（含字标）。
- 不拉伸、不加渐变外框、不替换主色；应用图标统一使用圆角方块版本。

## 3. 设计系统摘要

UI 风格参考 Ceres 与 Neptune 的共同语言，并针对工作记录场景做收敛：

- 左侧导航 + 主内容区的仪表盘布局，不出现营销化大 Banner。
- 苹果式玻璃材质：`backdrop-filter: blur(20-24px) saturate(160-180%)`，半透明层级 + 高光描边。
- 8px 圆角（卡片/按钮/输入框），胶囊用于标签，4pt 网格（4/8/12/16/24/32/48）。
- 字体优先 `Segoe UI Variable`，回退 `Inter` 与 `Microsoft YaHei UI`；字母间距恒为 0。
- 动效克制：按钮按下 100ms 内即时反馈，面板切换 200-300ms，尊重系统减少动态效果设置。

完整规范见 `design/ui-design-system.md`。

## 4. 技术选型

### 4.1 约束与目标

- 仅面向 Windows 10/11 桌面端。
- 需要高度自定义的「现代高级」UI，前端表达力要求高。
- 本地数据优先，安装包小、启动快、资源占用低。
- 需要系统通知、托盘、附件文件管理、导出等桌面能力。
- 后续需要接入大模型，并允许模型调用受控软件操作。

### 4.2 方案对比

| 方案 | 前端能力 | 体积/启动 | 本地存储 | 生态/维护 | 结论 |
| --- | --- | --- | --- | --- | --- |
| Tauri 2 + React + TS | 高，完全自定义 | 极小，启动快 | SQLite（Rust） | 活跃，Vite 生态 | 推荐 |
| Electron + React | 高 | 大，内存高 | SQLite/IndexedDB | 成熟但重 | 备选 |
| WinUI 3 + C#/.NET | 中，自定义成本高 | 中 | SQLite（EF Core） | 微软官方 | 备选 |
| Avalonia + .NET | 中高 | 中 | SQLite | 生态较小 | 不推荐 |

### 4.3 选定技术栈

**主选：Tauri 2 + React + TypeScript + Vite**

- **桌面外壳**：Tauri 2（Rust），负责窗口、自定义标题栏、系统通知、托盘、文件操作与打包。
- **前端**：React + TypeScript + Vite，承载全部品牌 UI。
- **样式**：自研 CSS 设计令牌 + 轻量 CSS，不引入重型组件库，保证品牌一致性。
- **状态**：Zustand（UI 状态）+ TanStack Query（数据请求与缓存）。
- **图标**：`lucide-react`，与系统级质感统一。
- **数据层**：SQLite（`rusqlite` bundled），数据量小、可查询、可备份、可迁移。
- **测试**：Vitest + React Testing Library；E2E 使用 Playwright。
- **AI 网关**：Rust `reqwest` 调用 OpenAI 兼容接口，SSE 流式输出；工具调用通过受控 allowlist。

**备选：WinUI 3 + C#/.NET 8**

当「原生 Windows 手感」优先于开发速度与自定义 UI 时启用；但完全自定义苹果式高级 UI 的成本更高。

### 4.4 关键技术理由

- 不使用 Electron：个人工具场景下，其运行时体积与内存占用没有收益。
- 使用 Web 技术栈而非纯 Rust 前端：品牌 UI 需要快速迭代，React 表达力最高。
- 使用 SQLite 而非 JSON/IndexedDB：需要按项目、日期、标签聚合查询，并支持增量导出。
- 附件不入库：文件按哈希目录保存在应用数据目录，数据库只存元数据，避免数据库膨胀。
- AI 工具调用走 Rust 命令层：模型只接触白名单工具，写操作需用户确认，操作有审计日志。

### 5.3 数据模型（MVP）

```sql
CREATE TABLE projects (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  color TEXT,
  status TEXT NOT NULL DEFAULT 'active',
  created_at TEXT DEFAULT (datetime('now')),
  archived_at TEXT
);

CREATE TABLE work_entries (
  id INTEGER PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id),
  work_date TEXT NOT NULL,
  started_at TEXT,
  ended_at TEXT,
  title TEXT NOT NULL,
  content TEXT,
  tags TEXT,
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE attachments (
  id INTEGER PRIMARY KEY,
  entry_id INTEGER REFERENCES work_entries(id),
  file_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  mime_type TEXT,
  size_bytes INTEGER,
  created_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE report_templates (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL,           -- daily / weekly
  body_json TEXT NOT NULL,
  variables_json TEXT,
  is_default INTEGER DEFAULT 0,
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE reports (
  id INTEGER PRIMARY KEY,
  template_id INTEGER REFERENCES report_templates(id),
  type TEXT NOT NULL,
  start_date TEXT NOT NULL,
  end_date TEXT NOT NULL,
  content TEXT NOT NULL,
  exported_at TEXT
);

CREATE TABLE ai_tool_logs (
  id INTEGER PRIMARY KEY,
  session_id TEXT,
  tool_name TEXT NOT NULL,
  args_json TEXT,
  status TEXT NOT NULL,
  created_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT
);
```

## 7. 里程碑路线图

### M0 品牌与工程骨架（约 2 天）

- Logo、品牌板、设计令牌落地为 CSS 变量。
- Tauri 2 + React + TS 脚手架初始化。
- 自定义标题栏、无边框窗口、深浅主题、玻璃材质。
- 接入技能并生成 Windows 图标。

### M1 项目与记录闭环（约 5 天）

- 项目 CRUD 与归档。
- 工作记录：按日期/项目记录标题、内容、标签、起止时间。
- 附件：拖拽添加、元数据入库、双击打开、删除。
- 今日视图与时间线，基础单元测试。

### M2 数据分析（约 5 天）

- 日期/项目/标签筛选。
- 每日时长、项目占比、趋势图、热力图。
- 导出 CSV/JSON。

### M3 日报/周报与模板（约 5 天）

- 模板设计器：区块、变量、项目与日期占位。
- 日报/周报自动生成、预览、导出 Markdown/HTML。
- 记录缺失与未填写项目的提示。

### M4 AI 能力接入（约 6 天）

- 设置页：API 提供商、模型、密钥（系统凭据库）。
- AI 助手面板：流式对话，引用当前视图上下文。
- 工具桥：把白名单 Tauri command 转为模型 function tool。
- 写操作需用户确认，工具调用写入审计日志。

### M5 打磨与发布（约 4 天）

- 空态、错误态与边界输入。
- 无障碍：键盘操作、`prefers-reduced-motion`、对比度检查。
- 打包安装程序与图标验证。
- 端到端冒烟测试并发布 v0.1。

总周期约 3-4 周；M1-M2 可并行推进一部分基础数据层。

## 8. 日常开发流程与命令

### 8.1 前置环境

- Windows 10/11，已安装 WebView2 Runtime（Win11 自带，Win10 需安装）。
- Node.js 20+ 与 npm。
- Rust stable + VS Build Tools（C++ 生成工具，Tauri 编译需要）。
- 全局或项目级 Tauri 2 CLI。

### 8.2 常用命令

| 命令 | 用途 |
| --- | --- |
| `npm install` | 安装前端依赖 |
| `npm run tauri dev` | 开发模式：Vite HMR + 窗口热启动 |
| `npm test` | Vitest 单元测试 |
| `npm run build` | 构建 React 前端产物 |
| `npm run tauri build` | 构建 Windows 安装包（NSIS） |
| `cargo check` | 仅检查 Rust 代码，不产生二进制 |
| `python scripts/make_logo_png.py` | 重新生成 1024px 品牌 PNG |
| `npm run tauri icon assets/brand/logo-icon-1024.png` | 生成 Windows/应用图标 |

### 8.3 开发循环

1. 改前端：Vite 热更新，无需重启窗口。
2. 改 Rust 接口：保存后运行 `cargo check`，再 `npm run tauri dev` 重启。
3. 数据库变更：在 `src-tauri/src/core/db.rs` 增加版本化迁移，不直接改已发布表。
4. 每个里程碑结束时运行 `npm test` 与 `npm run tauri build` 冒烟验证。

前端调用后端统一走 `@tauri-apps/api/core` 的 `invoke`，不在前端直接访问文件系统；附件路径与数据库访问只发生在 Rust 层。

## 9. Windows 打包与图标

- 用 `npm run tauri icon assets/brand/logo-icon-1024.png` 生成 `src-tauri/icons/` 全部尺寸图标。
- `tauri.conf.json`：`productName` 为 `Mars`，identifier 建议 `com.mars.desktop`。
- 打包目标以 NSIS 安装器为主，后续按需增加 MSI。
- 首次发布先做未签名包；正式发布前再接入代码签名证书。
- WebView2 采用系统运行时，不随安装包内嵌，安装脚本检查缺失并提示。
- 附件目录默认放 `%APPDATA%\Mars\attachments`，数据库放同目录，设置页提供备份路径。

## 11. 风险与备选方案

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 目标机缺少/旧版 WebView2 | 窗口无法启动 | 安装脚本检测并引导下载运行时；仍不可用则评估退回 Electron |
| 附件文件多且大 | 数据库膨胀、备份慢 | 附件按哈希目录存磁盘，库只存元数据；提供“复制到附件库”与“仅链接”两种模式 |
| AI 接口网络不稳定或密钥泄露 | 主流程被拖慢、安全风险 | 核心功能零 AI 依赖；密钥存系统凭据库，SSE 带超时与重试 |
| 数据库结构演进 | 升级后数据损坏 | 使用版本化迁移表，升级前自动备份 |
| 报告排版依赖浏览器 | 打印/PDF 效果不稳定 | 报告用专用打印 CSS，HTML 预览先行；docx/PDF 后续用独立渲染器 |
| 暖色单一化 | 界面疲劳、对比度不足 | 用冷灰承担结构信息，数据图表引入绿色/琥珀/紫色系列 |
